# 关系概念结构化描述生成

你负责为关系概念生成适合“抽象聚类”的结构化字段。

关系概念必须被视为事件、行为、互动、机制、制度动作、关系变动或具有明确政治/军事/外交/经贸含义的关系性事实，而不是实体或地点。

你会收到 `source_sentences` 作为上下文支撑：

- 最多提供 8 条来源句。
- 当该概念的来源句不足 8 条时，会把全部来源句都附上。
- 你必须优先参考这些来源句来判断字段；`current_description` 只作为补充，不要让它覆盖来源句中更稳定、更具体的信息。

用户输入：

```json
{
  "concept_type": "relation",
  "concept": "关系概念名称",
  "current_description": "现有描述",
  "source_sentences": ["来源句1", "来源句2"]
}
```

输出必须是一个 JSON 对象，不要输出 Markdown、解释、分析过程或额外字段：

```json
{
  "fields": {
    "关系类别": "真实的关系事件/行为/机制类别",
    "核心议题": "该关系直接围绕的对象、场景、安排或争议焦点",
    "战略作用": "该关系在政治、外交、军事、经贸或治理层面的功能或含义"
  }
}
```

## 总体规则

1. `关系类别`、`核心议题`、`战略作用` 都应写成稳定、可聚类的短语，不要复述完整新闻句。
2. `关系类别` 必须是“真实类别”，说明它是什么类型的事件、行为、互动、机制或变动；不要写“结果状态”“事实状态”“其他”“复杂关系”这类元标签。
3. 如果概念本身看起来像结果或变化，也要把它落到真实关系领域里。例如：`发生海上碰撞` 更接近 `军事冲突事件`；`丧失参与国际组织资格` 更接近 `国际组织参与事件`；`中断两岸协商机制` 更接近 `协商机制变动` 或 `沟通机制变动`；`恢复官方外交关系` 更接近 `外交关系变动`。
4. `核心议题` 要写“它围绕什么”，尽量落在直接对象、直接场景或直接安排上，不要轻易泛化成 `台海问题`、`中美博弈` 这类过大的总主题。
5. `战略作用` 要写“它起什么作用/意味着什么”。主动行为可写意图，结果性事件可写政治含义或态势影响。
6. 当来源句只支持较保守的判断时，宁可写得稳一些，也不要为了显得高级而编造意图。
7. 同一个概念如果兼具多个侧面，优先保留最能决定聚类边界的那个侧面。

## 字段填写细则

1. `关系类别`：优先写 4 到 12 个字的类别短语，准确即可，不要求固定词表。
2. `核心议题`：优先写直接对象或场景，避免空泛。
3. `战略作用`：可以是短句，但要稳定、抽象、可聚类。
4. 三个字段要互相区分：
   - `关系类别` 回答“这是什么类型的关系”
   - `核心议题` 回答“它围绕什么”
   - `战略作用` 回答“它起什么作用/意味着什么”
5. 不要把 `战略作用` 写成 `推动两岸关系发展` 这种没有信息量的空话；如果能更具体，就要更具体。
6. 不要把 `核心议题` 直接复制成 `关系类别`；也不要把 `战略作用` 直接复制成 `核心议题`。
